# 분석 결과 뷰어 (UI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `python app.py`로 뜨는 로컬 웹 뷰어: 랠리 복기 탭(영상 + 박스·공·이벤트 겹침 + 코트 지도)과 경기 통계 탭.

**Architecture:** 순수 함수 모듈 `viewer_data.py`(CSV → 랠리·구간·통계)를 `app.py`(FastAPI 앱 + 실행 진입점)가 얇게 감싸고, `ui/`의 순수 HTML/JS가 API와 영상(Range)을 받아 canvas에 겹쳐 그린다. 분석 산출물은 읽기만 한다.

**Tech Stack:** Python(FastAPI, uvicorn, pandas, cv2 — 모두 설치돼 있음), 순수 HTML/JS/CSS(빌드·CDN 없음), pytest + FastAPI TestClient(httpx).

**Spec:** `docs/superpowers/specs/2026-11-19-ui-viewer-design.md`

## Global Constraints

- 실행: `python app.py [--outputs outputs] [--data data] [--port 8000]`, 인터넷 없이 동작, 런타임 CDN 금지.
- 분석 산출물 형식 변경 금지. `outputs/<이름>_{rallies,events,tracks,ball}.csv`, `_analysis.png`는 읽기 전용.
- 파일 읽기·쓰기는 항상 `encoding="utf-8"` (Windows 기본 cp949).
- 경기 = `outputs/<이름>_rallies.csv`에 **행이 1개 이상**인 이름. 영상은 `data/<이름>.mp4`.
- fps는 영상 파일에서 읽고, 영상이 없으면 29.97. CSV의 frame·start·end·peak은 같은 번호(0부터).
- 팀은 `LEFT`/`RIGHT`, LEFT 빨강·RIGHT 파랑. 코트 지도: 가로축 `court_y`(0~18 m, 작은 쪽이 LEFT), 세로축 `court_x`(0~9 m).
- 랠리 재생 구간 = `start−2초` ~ `end+2초`(0과 `프레임수−1`로 자름), 이벤트 = `start ≤ event.start < 랠리 끝`, winpoint 제외.
- "근거 부족": 접촉 ≤2, 또는 길이 <5초, 또는 득점 팀 없음. "코트 인식 실패": 선수 행이 연속 30프레임 이상 없는 구간.
- 통계는 `analysis.py`와 같은 정의 (득점=랠리 승수, 서브 득점률=서브한 랠리 중 승, 사이드아웃률=리시브한 랠리 중 승, `winner` 없는 행 제외).
- 상시 표시 문구: "득점 팀 판정 약 85% (득점 팀은 다음 랠리의 서브 팀으로 추정)".
- 영상·캡처·GIF는 git에 안 넣는다. `ui_cache/`는 만들지 않는다 (아래 Task 2 노트).

## Review Focus

1. 랠리 구간이 영상 끝을 넘는 경우 (마지막 랠리) — 구간을 영상 범위로 자르고 깨지지 않는다.
2. 선택적 CSV가 없거나 비었을 때(`_ball.csv`·`_tracks.csv` 없음, `_events.csv` 비어 있음) — 빈 결과로 응답하고 화면에 안내가 뜬다.
3. 마지막 랠리의 `winner`가 빈칸(NaN) — 통계에서 제외하고 목록에는 "득점 팀 없음"으로 표시.
4. `/frames` 요청의 비정상 구간 (`start>end`, 음수, 6000프레임 초과) — 400.
5. 경기 이름에 경로 문자(`..` 등)를 넣은 `/video/{stem}`·`/api/matches/{stem}/…` — 목록에 없는 이름은 404, 파일 시스템에 닿지 않는다.
6. Range 요청이 파일 크기를 넘는 경우 — 416이고 서버는 죽지 않는다.

### Task 1: 데이터 모듈 `viewer_data.py`

**Files:**
- Create: `viewer_data.py`
- Create: `test_viewer.py` (이 Task에서는 데이터 함수 테스트만)

**Interfaces:**
- Produces:
  - `find_matches(outputs: Path, data: Path) -> list[dict]` — 항목 `{stem, fps, frames, width, height, has_video, playable}`. `playable` = 영상 FOURCC가 `{"VP90","avc1","H264","AV01"}` 중 하나. 영상 없으면 `fps=29.97`, `frames/width/height=None`, `has_video=False`, `playable=False`.
  - `load_rallies(outputs, stem, fps, frames) -> list[dict]` — 항목 `{n(1부터), start, end, serve_team, winner(None 가능), contacts, seconds, window:[a,b], warn:list[str]}`. `end = start + round(seconds*fps)`. warn 문구는 `"접촉 2 이하"`, `"5초 미만"`, `"득점 팀 없음"`.
  - `rally_events(outputs, stem, start, end) -> list[dict]` — `{start,end,peak,team,action,actor,court_x,court_y}`, winpoint 제외, 빈 값은 None.
  - `frames_slice(outputs, stem, a, b) -> dict` — `{"players": [[frame,track_id,team,x1,y1,x2,y2,court_x,court_y,airborne],...], "ball": [[frame,x,y],...], "gaps": [[s,e],...]}`. team은 0=LEFT, 1=RIGHT, 그 외 −1. a..b 양끝 포함. 공 `x`·`y`가 빈 행은 버린다. 파일 없으면 빈 목록.
  - `no_court_gaps(frames_present: set[int], a: int, b: int, min_len: int = 30) -> list[list[int]]` — a..b에서 `frames_present`에 없는 연속 구간 중 길이 ≥ min_len인 것의 `[첫 프레임, 마지막 프레임]`.
  - `summary(rallies) -> dict` — `{"rallies": 전체 수, "LEFT": {points, serves, serve_wins, receives, receive_wins, serve_rate, sideout_rate}, "RIGHT": {...}}`. 분모 0이면 rate는 None.

### Task 2: API 서버 `app.py`

**Files:**
- Create: `app.py`
- Modify: `test_viewer.py` (API 테스트 추가)

**Interfaces:**
- Consumes: Task 1의 모든 함수, `make_outputs`.
- Produces: `create_app(outputs: Path, data: Path) -> FastAPI`, `main()`(argparse `--outputs --data --port`, uvicorn 실행, 1초 뒤 `webbrowser.open`).
  - `GET /api/matches` → `find_matches` 결과
  - `GET /api/matches/{stem}/rallies` → `load_rallies` 결과 + 각 항목에 `events`(= `rally_events`)
  - `GET /api/matches/{stem}/summary` → `summary`
  - `GET /api/matches/{stem}/frames?start=&end=` → `frames_slice` (400: `start>end`, `start<0`, `end-start>6000`)
  - `GET /api/matches/{stem}/figure` → `<stem>_analysis.png` (없으면 404)
  - `GET /video/{stem}` → `FileResponse(media_type="video/mp4")` (Starlette가 Range 처리)
  - `GET /` → `ui/index.html`, `/static/*` → `ui/` 폴더
  - 목록에 없는 `{stem}`은 모든 엔드포인트에서 404.

  - `test_api_summary`: Task 1 `test_summary`와 같은 숫자.

**노트:** 영상 H.264 변환(spec의 "내 판단")은 이번에 구현하지 않는다. 경기 목록에 들어오는 영상은 모두 VP9라 변환이 필요한 경우가 없고, 데이터셋 클립은 랠리가 없어 목록에 안 나온다. `playable:false`면 화면이 "이 영상 형식은 브라우저에서 재생할 수 없음"을 안내한다 (Task 3).

### Task 3: 화면 `ui/`

**Files:**
- Create: `ui/index.html`, `ui/app.js`, `ui/style.css`

**Interfaces:**
- Consumes: Task 2의 API.
- Produces: 화면(자동 테스트 없음, 아래 확인 단계로 검증).

화면 구성: ① 상단 줄 — 경기 선택 `<select>`, 탭 두 개(복기 / 경기 통계), 상시 안내 "득점 팀 판정 약 85% …". ② **복기 탭** — 왼쪽 랠리 목록(번호, 시작 시각 `mm:ss`, `서브 팀 → 득점 팀`, 접촉 수, 길이, 주의 배지(warn 문구는 툴팁)); 오른쪽 위 `<video>` + 같은 크기의 `<canvas>` 겹침, 그 아래 타임라인(랠리 구간 막대, 이벤트 마커, `gaps`는 회색 + "코트 인식 실패" 툴팁); 오른쪽 아래 코트 지도 canvas(현재 프레임 선수 점 + 접촉 위치를 번호 붙여 순서대로 연결)와 랠리 요약(서브 팀, 득점 팀, 접촉 수, 길이). ③ **통계 탭** — 팀별 카드(득점, 서브 득점률, 사이드아웃률, 분모 표기 `5/15`), 그 아래 `<img src="/api/matches/{stem}/figure">`(404면 숨김). 색·간격은 `style.css` 상단 `:root` CSS 변수에만 둔다.

동작 규칙: 랠리 선택 시 `/frames?start=a&end=b`를 받고 `video.currentTime = a/fps`로 이동·재생, 프레임 `f`가 `b` 이상이면 일시정지. 겹침 그리기는 `video.requestVideoFrameCallback((now, meta) => …)`의 `meta.mediaTime*fps`를 반올림한 프레임 번호로 그 프레임의 선수·공을 그리고(꼬리 = 직전 12프레임 공 위치), 좌표는 영상 원본 해상도(`frames`가 아니라 `/api/matches`의 width/height)에서 표시 크기로 비례 변환한다. 해당 프레임에 선수 행이 없으면 캔버스에 "코트 인식 실패 구간" 글자를 띄운다. ↑/↓ 키로 이전/다음 랠리. 영상이 없거나 `playable:false`면 영상 영역에 안내 문구를 띄우고 통계 탭은 그대로 쓴다.

- [ ] **Step 2: 서버를 띄운다** — `python app.py --port 8000` (백그라운드).
- [ ] **Step 3: 화면 확인 — 구조** — 내장 브라우저로 `http://localhost:8000`을 열어 확인: 경기 선택에 `match1_set1/2/3`, 첫 경기의 랠리 40개 목록, 콘솔 에러 0, 통계 탭에 카드와 그림, 상단 안내 문구 표시.
- [ ] **Step 4: 화면 확인 — 동기화 (가장 중요)** — 1세트에서 선수가 많이 보이는 랠리 하나(예: 목록에서 접촉 수가 많은 랠리)를 골라 재생 중 3지점에서 일시정지 후 확대 스크린샷으로, ⓐ 박스가 실제 선수 몸에 맞는지 ⓑ 공이 보이는 프레임에서 노란 원이 공에 맞는지 확인한다. 박스가 선수에서 한 칸 이상(한 선수 폭 이상) 밀려 있으면 실패: fps/프레임 번호 변환을 고친다. 결과를 캡처 파일로 `outputs/ui_check/`(git 제외)에 남긴다.
- [ ] **Step 5: 화면 확인 — 예외 상황** — (ⓐ) 마지막 랠리(득점 팀 없음 배지, 영상 끝에서 멈춤), (ⓑ) `gaps`가 있는 랠리에서 회색 구간과 안내 문구, (ⓒ) 2세트·3세트로 전환해도 목록·영상이 바뀐다.
- [ ] **Step 6: 커밋** — `git add ui && git commit -m "feat: 뷰어 화면 (복기·경기 통계 탭)"`.
